# 中文会议 ASR 与说话人分区 CPU 测试总报告

报告按数据来源分成两组：

- **公开测试数据**：AISHELL-4 和 AliMeeting 共 11 段、780 秒，用于比较转写、分区和性能。cpCER 与 DER 按各自的人工标注范围计算。
- **Clip 真实录音**：设备上传的 3 条完整录音，共 1164.18 秒，用于比较实际运行耗时、CPU 开销和输出差异。该组缺少人工参考，发布内容为匿名汇总指标。

公开测试覆盖 2026-11-06 的本机测试和 2026-11-08 的服务器测试。本机为 Apple M5 Pro（15 个逻辑 CPU），服务器为 Intel Xeon Platinum 8488C（系统可见 8 个逻辑 CPU）。两端均配置 4 个计算线程、1 个调度线程，串行测试。完整流程耗时包含识别、适用的标点、对齐和分区阶段，模型加载、热身和写结果另计。

实时倍数 = 音频秒 / 流程耗时。服务器 / 本机的比值大于 1 表示服务器耗时更长。FireRed 的本机 beam=3、服务器 beam=1，分别保留三个和一个搜索候选，因此只列各自实测值。各流程采用各自兼容的运行时，差异反映实测配置与环境。

cpCER 为匿名说话人最优配对后的字符插入、删除、替换总数除以参考字符数，衡量文字和归属的联合错误。只在 AISHELL-4 五段的 53 个完整参考区间和 1071 个规范化字符上评分。例如 MOSS 的 96 / 1071 为 8.96%。

累计 CPU 秒为各线程在用户态和内核态消耗的时间之和。平均进程 CPU = 累计 CPU 秒 / 流程墙钟秒 × 100%，100% 表示平均占用一个逻辑核。Qwen 在服务器的 397.2% 相当于平均约 3.97 个核，除以 8 后约占可见 CPU 容量的 49.7%。本机有同批逐阶段 CPU 实测的三套流程列出了对应数值，破折号表示其余流程缺少同口径本机数据。

RSS 为进程驻留内存，服务器以约两秒的间隔采样，统计包括加载在内的 ASR 进程峰值。1 GiB = 1,073,741,824 字节。耗时、占用与累计 CPU 秒应一起看。[本机 CPU 测量方法](cpu-method.md)

## Clip 真实录音

### 与公开测试数据对比

Clip 实录组使用 3 条完整录音，共 1164.18 秒，最长一条 1147.18 秒。两套方案在同一台服务器上串行运行。下表对照同模型在公开样本与实录上的表现。

| 服务器测试组 | 流程 | 完整流程秒 | 平均进程 CPU | 实时倍数 |
| --- | --- | --- | --- | --- |
| 公开主集（600 秒） | Qwen 0.6B + Nemotron 3 | 164.02 | 397.2% | 3.66× |
| 公开主集（600 秒） | MOSS 0.9B | 476.85 | 399.8% | 1.26× |
| 公开连续补测（180 秒） | Qwen 0.6B + Nemotron 3 | 48.03 | 397.2% | 3.75× |
| 公开连续补测（180 秒） | MOSS 0.9B | 251.45 | 399.6% | 0.72× |
| Clip 真实录音（1164.18 秒） | Qwen 0.6B + Nemotron 3 | 303.60 | 398.2% | 3.83× |
| Clip 真实录音（1164.18 秒） | MOSS 0.9B | 1137.98 | 399.5% | 1.02× |

实录中，MOSS 用时为 Qwen 组合的 3.75 倍，累计 CPU 分别为 4546.36 和 1208.80 CPU 秒。两套流程平均都占用约四个逻辑核。MOSS 长录音采用最多 180 秒窗口和 15 秒重叠，重叠计算计入耗时，实时倍数以原录音时长为分母。公开与实录组音频内容和长度不同，实时倍数反映各自测试条件。

在最长一条录音上，Qwen 输出 259 行，中位行跨度 3.55 秒，MOSS 输出 235 行，中位 2.01 秒，最长 34.07 秒。两套输出对齐到相同字符后有 117 个共同的标点句末。Nemotron 给出 8 个标签，达到模型的标签槽位上限，MOSS 拼接后有 17 个标签，其中 13 个跨窗口标签缺少接续证据。两边均有语音的时间内，最佳匿名配对后至少一个标签同时活跃的比例为 51.6%。

实录组没有人工文字、句界和说话人参考。公开组的 cpCER 与 DER 来自有标注的样本，实录组的行跨度、标签数与配对一致度用于定位复核。
