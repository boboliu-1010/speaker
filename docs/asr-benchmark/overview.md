## Clip 实录

3 条完整上传录音，共 1164.18 秒，最长一条 1147.18 秒。两套流程在同一台服务器串行执行。

### 服务器性能

| 流程 | 完整流程秒 | 平均进程 CPU | 累计 CPU 秒 | 实时倍数 |
| --- | ---: | ---: | ---: | ---: |
| Qwen 0.6B + Nemotron 3 | 303.60 | 398.2% | 1208.80 | 3.83 |
| MOSS 0.9B | 1137.98 | 399.5% | 4546.36 | 1.02 |

### 长录音输出

| 指标 | Qwen 0.6B + Nemotron 3 | MOSS 0.9B |
| --- | ---: | ---: |
| 转写行数 | 259 | 235 |
| 行跨度中位数 | 3.55 秒 | 2.01 秒 |
| 分区标签数 | 8（达到槽位上限） | 17（13 个缺少跨窗接续证据） |

两份长稿的字符差异率为 18.4%（971 / 5285）。两边均检出语音时，最佳配对后至少一个说话人标签同时活跃的时间占比为 51.6%。实录缺少人工参考稿，暂不计算 cpCER 或 DER。

检查对象为 16 kHz、16-bit 单声道 WAV。0 dBFS 为数字满量程，低电平帧包含停顿。

## 结论

**Clip 默认用 Qwen 0.6B + Nemotron 3。** 实录处理速度为 3.83×，MOSS 为 1.02×，两套平均都占用约 4 个逻辑核。MOSS 在标准数据上的 cpCER 和 DER 更低，可作为第二份稿供核对。Clip 短录音的主要内容七套模型均能转出，长录音整体电平较低（−34.8 dBFS RMS），波形未见持续触顶。长会议里的专有名词、数字和多人交接仍需回听。
