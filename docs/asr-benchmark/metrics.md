## 转写质量 cpCER

cpCER 是**文字及说话人归属的联合字符错误率**。先将每位说话人的文本按时间串接，再为参考与模型的匿名标签寻找总编辑错误最少的对应关系。A/B 标签单纯互换不会受罚；文字放到错误的说话人串中会影响分数。

`cpCER = 最优标签匹配后的（替换数 + 删除数 + 插入数）/ 参考字符总数 × 100%`

| 本轮结果 | 分子和分母 | 如何理解 |
| --- | --- | --- |
| FireRed 17.09% | 183 / 1071 × 100% | 参考的 1071 个字符对应 183 次联合编辑错误。不是“17.09% 的句子错误”或“17.09% 的人认错”。 |
| Qwen 10.64% | 114 / 1071 × 100% | 同一参考范围内为 114 次联合编辑错误。 |
| MOSS 8.96% | 96 / 1071 × 100% | 同一参考范围内为 96 次联合编辑错误。 |

字符包括汉字、英文字母和数字；英文按字符计，不按单词计。评分统一全半角、转小写、去标点和事件标签，数字不改写。这里还受自动时间对齐和边界筛选影响；它不是只测 ASR 文字的独立 CER，也不是业务准确率。大量额外插入可使错误率超过 100%。

**主表的 cpCER 不覆盖 AliMeeting。** 例如 FireRed 在 AliMeeting 的长重复，即使很严重，也不会增加这个五场 AISHELL-4 指标。因此选型同时看全文、可靠性计数和耗时。

## 耗时 速度与 CPU

| 表中数值 | 单位与公式 | 实际含义及读法 |
| --- | --- | --- |
| 完整耗时 / 处理十分钟耗时 | 墙钟秒；各串行推理阶段耗时相加 | 最新 FireRed 1128.0 秒约为 18 分 48 秒；Qwen 87.9 秒约为 1 分 27.9 秒；MOSS 251.8 秒约为 4 分 11.8 秒。包括识别、适用的标点、字级对齐和分人；排除下载、加载、热身、读音频及结果写盘。它是测得的流程推理时间，用户冷启动、排队及网络等待需另加。 |
| ASR 耗时 | 墙钟秒；只累计 ASR 阶段 | FireRed 主集 1108.1 秒只对应识别阶段。MOSS 的 ASR 阶段同时产生原生说话人；Paraformer / SenseVoice 历史 runner 的该阶段还包含 CT-Punc。必须结合阶段说明读数。 |
| 实时倍数 | 音频秒 / 处理墙钟秒，越高越快 | Qwen `600 / 87.8538 ≈ 6.83`，表示每秒计算处理约 6.83 秒音频。FireRed `600 / 1127.9659 ≈ 0.53`，表示处理速度慢于录音时长，十分钟输入需要约十八分四十八秒计算。 |
| RTF | 处理墙钟秒 / 音频秒，越低越快 | 是实时倍数的倒数。Qwen 最新完整流程约为 0.146；RTF 小于 1 表示计算耗时短于音频时长。这是离线处理吞吐，不代表已验证实时流式产品延迟。 |
| 平均进程 CPU | `100 × 累计 CPU 秒 / 推理墙钟秒` | 单核满载为 100%。Qwen 177.5% 约为平均占用 1.775 个核；FireRed 124.3% 约为 1.243 个核。表示全部测试线程合计的平均核时间，不是质量分数、不是四核配额的百分比，也不表示固定占住哪几个核。 |
| 平均占用核数 | 平均进程 CPU / 100 | JSON 中 Qwen 为 1.7751。它是核时间的平均等效值，不是线程数或 CPU 绑核设置。 |
| 折算整机 CPU | 平均进程 CPU / 本机 15 核 | Qwen `177.5109 / 15 ≈ 11.8%`，FireRed约为 8.3%。只表示测试进程消耗的核时间占整机核时间预算的比例；其他应用占用另计。不是采样得到的整机总忙碌率，各核的频率和性能也不由该比例表达。 |
| 累计 CPU 秒 | 各测试进程的用户态 CPU 秒 + 内核态 CPU 秒，再按阶段相加 | 两个核各忙 1 秒，累计为 2 CPU 秒。Qwen 完整主流程累计 155.9 CPU 秒，但墙钟为 87.9 秒；FireRed 累计 1402.4 CPU 秒。可同时衡量占用和持续时间；不是用户等待时间，也不是瓦数或电量，功耗未测。 |
| 最快一段 / 最慢一段 | 十个不同 60 秒输入的 ASR 耗时最小值 / 最大值 | FireRed 43.8–464.1 秒是跨十段录音的范围；464.1 秒约为 7 分 44 秒。不是同一录音反复测试的波动范围，不是 P95，也不含后续外部分人和对齐。MOSS 原生分人包含在该阶段。 |
| 耗时比 12.84 / 4.48 | FireRed 完整耗时 / 另一流程完整耗时 | 分别为 `1127.9659 / 87.8538` 和 `1127.9659 / 251.8260`。表示这批输入的耗时比，不是错误率差、CPU 占用比或通用硬件性能倍数。 |
| ↑ / ↓ | 阅读方向 | ↑ 表示希望更高，如实时倍数；↓ 表示希望更低，如错误率与耗时。CPU 占用高低需与耗时一起看，不能单独判断效率。 |

总 CPU 平均值按“各阶段 CPU 秒之和 / 墙钟秒之和”计算，不能把逐行百分比直接做算术平均。最新三套流程的平均 CPU 都只统计正式推理，不含其他应用；没有测瞬时 CPU 最大值。首轮六模型的表没有采集 CPU 占用，不用新一轮百分比回填旧轮。

## 内存 参数与数值精度

| 数值 | 具体含义 |
| --- | --- |
| ASR 峰值内存 5.03 / 3.93 / 4.30 GiB | 最新 FireRed、Qwen、MOSS 的 ASR 进程生命周期最大 RSS，即操作系统记录的峰值驻留内存。包含加载、热身、推理与依赖库；不是平均值、权重文件大小或全部阶段同时占用。进程顺序处理 11 段，因此主集和补测引用同一个进程峰值。 |
| GiB 与 GB | 1 GiB = 1,073,741,824 字节；1 GB = 1,000,000,000 字节。例如 3.93 GiB 约为 4.22 GB；表中使用 GiB。 |
| 24 GiB | 本机物理内存容量，不是给模型独占分配的内存上限，也不是实际已用量。 |
| 模型名 0.6B / 0.9B / 1.7B | B 表示十亿量级的参数规模标称名称，不是 GB 内存。完整参数数以本地加载后的统计为准： Qwen 0.6B 782,426,112、MOSS 908,513,280、Qwen 1.7B 2,038,052,480。FireRed 实测为 1,152,521,275。 |

| 权重 4,731,558,506 字节 | FireRed 检查点文件的磁盘体积；文件含参数和元数据，不等于运行内存。SHA-256 / revision 是内容和版本标识，不是准确率或性能数字。 |

## 分区质量 DER

`DER =（漏检说话人秒 + 误报说话人秒 + 说话人混淆秒）/ 参考说话人秒 × 100%`

- **漏检**：参考有人说话，模型没有覆盖对应的说话活动。
- **误报**：模型给出额外说话活动。
- **混淆**：活动时间被分配给错误的匿名说话人。先做最优标签匹配，不因 A/B 单纯改名受罚。
- **说话人秒**：两个人同时讲话 1 秒，参考累计为 2 说话人秒；同一人的时间自重叠取并集，不重复算。

| 表中数值 | 含义 |
| --- | --- |
| 整体 DER | 十段主测试的错误说话人秒相加，再除以参考说话人秒总和；不是十个百分比的简单平均。 |
| AISHELL-4 DER / AliMeeting DER | 各自五段内以同样方法汇总。子集人数和重叠程度不同，不能拿两列百分比直接平均来重建整体。 |
| Nemotron 3 的 13.56% | 零 collar 主集：`(70.370240 + 13.993421 + 5.771458) / 664.956819 × 100% ≈ 13.56%`。600 秒音频有重叠，所以参考为约 664.96 说话人秒。 |
| 三分钟补测 19.05% / 10.63% | 只在那一段 180 秒音频的人工分区参考上评分；前者为共享的 Nemotron 3，后者为 MOSS。两者不是说话人数，也不是文字错误率。 |
| 零 collar / `der_zero` | 不在人工参考边界附近额外排除时间，时间偏差也会计入。总览的 DER 默认采用这个设置。 |
| collar 0.25 / `der_025` | 使用 pyannote 的总宽度 0.25 秒，即人工边界前后各 0.125 秒不评分。排除了部分难边界，同时改变分母；通常数值较低，不可与零 collar 混作同一成绩。 |
| 分区耗时 3.80 秒与 220.22 秒 | 首轮 Nemotron 3 的 3.80 秒只做分区；MOSS 的 220.22 秒同时做 ASR 与原生分区。两者任务范围不同，不能据它们直接算相同任务的速度比。 |

[分区误差的实际分子与分母](der-components.json)保留了本轮主集和补测的漏检、误报、混淆及参考说话人秒，可复算上述比例。

DER 越低表示参考分区下的活动归属误差越小；它不测识别文字、标点或自然句界，也不识别真实姓名。不能将 `100% − DER` 解释为“认对人的比例”。

## 可靠性次数的检查单位与分母

异常表中的“块”要按所属阶段读：FireRed / Qwen 以 30 秒 ASR 块生成；MOSS 每段音频生成一次，之后将原生带说话人的语音段分别送入对齐和重复检查。**这些次数的单位不同，不宜直接把块数当成会议失败率。**

| 检查项目 | FireRed / Qwen 主集、补测的检查数 | MOSS 主集、补测的检查数 |
| --- | --- | --- |
| 生成长度上限 | 20、6 个 ASR 生成块 | 10、1 次整段生成 |
| 字级对齐失败 | 20、6 个非空文字块 | 179、72 个非空原生语音段；主集另外 1 个空文本段跳过，共 180 个原生段 |
| 长重复 | 20、6 个 ASR 文字块 | 180、72 个原生语音段；空文本段不产生重复信号 |

- **0/20**：检查了 20 个单位，检测到 0 次该类事件；不是整体文字错误为零，也不是人工验收通过。
- **FireRed 长重复 3/20**：20 个主集 ASR 块中，3 块规范化后出现同字连续至少 8 次；来自 2 场会议。是复核信号，不能直接认定三个块都是幻觉，更不能说三场会议失败。全文保留并标待确认。
- **长度上限命中**：最终输出 token 数达到配置上限，可能有重复或截断。FireRed 只观察选中候选长度，没有记录全部 beam 的停止过程；0 次不证明内部搜索未耗尽步数。
- **对齐失败**：文字与时间对齐结果未通过长度、有限数值或时间范围等检查。这里不是说 ASR 一定失败；也不能把整块起止时间当作精确字级时间。
- **8 次阈值**：自动长重复检查阈值，不是 8 秒，也不是经过人工证明的幻觉判据；低于阈值、重复短语等其他错误可能没有触发。
- **512 / 2048 / 4096 token**：分别见 Qwen、MOSS 短片与长片的生成长度配置。token 是模型符号单元，可以是汉字、英文子词、控制标记或时间标记；不等于字符、单词、句子或音频秒数，不同模型不能直接按 token 上限比较。

## 时间 音频与解码参数

| 数值或标记 | 具体含义 |
| --- | --- |
| 原录音区间 150–210 秒 | 从来源录音的第 2 分 30 秒取到第 3 分 30 秒，片段长 60 秒。转写 00:10 对应原录音约 02:40。 |
| `[00:03.830–00:06.950]` | 相对片段起点的起止时间，分别为 3.830 秒和 6.950 秒；三位小数是毫秒显示精度，不表示已验证到毫秒级准确。重叠讲话允许时间重叠。 |
| A/B/C、A/C、待确认 | 匿名说话人标签；A/C 表示这句包含多个候选归属，未强行多数投票。待确认是复核提示，不是置信度百分比。不同模型的 A、不同会议的 A 不保证是同一个人。 |
| 16 kHz、单声道、PCM16 | 每秒 16,000 个音频采样点、一个通道、每个采样为 16 位整数。与模型 FP32 的计算精度是不同概念。 |
| 第 1 通道 | 多通道原录音固定取数组下标 0 的通道；没有逐样本挑最好通道。 |
| 30 / 60 / 180 秒分块 | 本实验的识别输入窗口。FireRed / Qwen 用 30 秒无重叠；MOSS 用整段 60 或 180 秒。不是句子长度或产品固件分片上限。 |
| 5 秒热身 | 正式计时前用首个主样本前 5 秒执行一次识别/对齐，让初始化路径先运行；这 5 秒的额外运行不计入正式耗时，但正式测试仍完整识别该片段。 |
| beam=3、nbest=1 | 搜索保留 3 个候选路径，最终返回 1 个最佳候选。不是检测 3 人、不是跑 3 次测试，也不表示只计算返回的那条路径。 |
| softmax smoothing=1.25 | FireRed 解码时将 logits 除以 1.25，再计算概率；是解码超参数，不是 125% 准确率。 |
| length penalty=0.6 | 序列长度归一化的指数；官方代码将候选累积分数除以 `((5 + 序列长度) / 6)^0.6`。不是模型标称 0.6B，也不是 0.6 秒。 |
| eos penalty=1.0 | 对结束符分数的乘数；1.0 表示不额外缩放，不表示结束概率为 100%。 |
| 版本号 2.10.0 / 5.17.0 等 | 软件包版本标识；点分数字不是耗时或质量，也不能按数值大小判断性能。v1 / v2.1、模型发布日期、Git commit 和哈希同样用于定位配置。 |

## CSV 和 JSON 字段对照

下列字段覆盖发布的三份 CSV 及两份汇总 JSON 的数值项；同名字段受所在文件与 `group` 限定。历史 `summary.json` 是首轮，`firered-cpu-summary.json` 是新三套复测；`primary` 为 600 秒主集，`long` 为 180 秒补测，`null` 表示未计算，不等于 0。

| 字段 | 单位与含义 |
| --- | --- |
| `samples`, `meetings`, `audio_samples`, `input_samples` | 所在分组的音频片段/session 数，或验证记录中的总数；`checks` 内为完整 11 段。 |
| `audio_seconds`, `source_start`, `source_end` | 音频长度，以及来源录音的裁剪起止秒；起止字段不是推理耗时。 |
| `samples_scored`, `reference_characters`, `edit_errors`, `cpcer_percent` | 实际评分样本数、规范化参考字符数、最优匹配总编辑错误数、联合错误率百分比。 |
| `primary_cpcer_reference_characters` | 验证记录中主集参考字符数 1071；新汇总 `checks` 内的数组按三模型各记一次相同的 1071，不是将参考相加成 3213 个字符。 |
| `pipeline_seconds` | 完整推理流程墙钟秒。 |
| `asr_seconds`, `alignment_seconds`, `diarization_seconds`, `inference_seconds` | 对应阶段的墙钟秒；独立分区的 `inference_seconds` 只分人，MOSS 的该字段还包含识别。 |
| `realtime_multiple`, `pipeline_realtime_multiple`, `asr_realtime_multiple` | 音频秒 / 对应流程或阶段的墙钟秒。不要把 ASR 倍数与完整流程倍数混比。 |
| `wall_seconds` | CSV 中为该模型、该样本、该阶段的墙钟秒；历史保护日志中为整个子进程运行时间，包含加载，范围不同。 |
| `cpu_seconds`, `pipeline_cpu_seconds`, `asr_cpu_seconds` | CSV 单阶段、完整流程、ASR 阶段的用户态与内核态累计 CPU 秒。 |
| `process_cpu_percent`, `pipeline_cpu_percent`, `asr_cpu_percent` | 相应范围的平均进程 CPU 百分比，以单核 100% 计。 |
| `machine_cpu_percent`, `pipeline_machine_cpu_percent` | 相应进程 CPU 百分比 / 15，为测试任务的整机核时间折算比例。 |
| `pipeline_average_busy_cores` | 完整流程平均进程 CPU 百分比 / 100。 |
| `peak_asr_process_rss_gib` | ASR 进程全生命周期最大 RSS，GiB。 |
| `fastest_asr_sample_seconds`, `slowest_asr_sample_seconds` | 该组内 ASR 阶段墙钟最小、最大秒；`slowest_asr_sample_id` 是对应输入标识。 |
| `alignment_failed_chunks`, `generation_limit_chunks`, `long_repeat_chunks` | 对齐失败、最终候选达到生成长度上限、长重复复核单位的数量；分母见可靠性说明。 |
| `reference_speaker_seconds`, `miss_seconds`, `false_alarm_seconds`, `confusion_seconds` | DER 参考说话人秒、漏检秒、误报秒、混淆秒；均按说话人数累计，单位为说话人秒，非普通音频墙钟秒。`der_percent` 为后三者之和 / 前者 × 100%。 |
| `speaker_der`, `der_zero`, `der_025`, `aishell_der_zero`, `ali_der_zero` | 分区错误率百分比；分别区分所在组、零 collar、0.25 秒 collar 和两个子语料库。 |
| `nemotron3`, `moss-0.9b`（DER 对象内） | 历史补测 JSON 中用模型名作键，键值为该模型的零 collar DER 百分比，不是参数量。 |
| `parameters` | 该模型实际参数元素总数，不是字节数。 |
| `human_speakers`, `pipelines`, `transcript_files`, `complete_transcripts` | 分别为该补测参考说话人数、验证流程数、生成转写份数；验证中的 33 与文档累计 73 的范围不同。 |
| `intraop_threads`, `interop_threads` | Torch 计算并行设置，单位为线程。 |
| `official_DER_crosschecks` | 22 次逐样本分区评分交叉核对：2 种分区模型 × 11 段；不是 22 场会议或 22 个模型。 |
| `exit_code` | 子进程退出码：0 表示正常退出，历史 -15 表示被 SIGTERM 终止；不是质量指标。 |
| `sampled_peak_rss_mb`, `rss_limit_mb` | 保护程序采样的进程峰值与停止阈值，实际按 MiB（1,048,576 字节）换算；采样峰值可能漏掉短峰，和生命周期最大 RSS 口径不同。字段保留旧名 `_mb`。 |
| `swap_before_mb`, `swap_after_mb`, `swap_growth_limit_mb` | 保护程序读到的整机交换空间用量与允许增长阈值，按 macOS `sysctl` 的 M 单位记录；属于整机诊断，不能全归因于单一模型，也不是物理内存或进程 CPU。 |

`cpu-by-sample-stage.csv` 共 99 条阶段记录：FireRed 4 阶段 × 11 段 + Qwen 3 阶段 × 11 段 + MOSS 2 阶段 × 11 段。99 不是样本数；FireRed/Qwen 各计入同一份 Nemotron 3 的阶段成本，是各自独立完整流程的比较口径。`stage` 名说明该行测了什么，`model` / `sample_id` 是标识，`group` 区分主集与补测。

证据文件中的 `bytes` / `total_bytes` 是文件字节数，SHA-256 和 revision 是可复核标识；`passed` / `status` 是检查结果，不是百分比。没有“断句正确率”“真实身份准确率”“CPU 峰值”或“耗电量”的有效实测数值；这些项目不能从现有表格换算得到。
